IDML Export — Support & Troubleshooting

Last updated: 25 August 2026

This page covers the companion app — Monochrome bridge — which is where nearly every support question about IDML Export ends up. If your problem is with the exported file itself rather than with getting an export to run at all, skip to The export ran, but the file is wrong.

Download the companion: monochrome-downloads.github.io/monochrome-services

"The companion isn't running"

This is the most common message, and it almost always means one of four things.

1. It isn't installed yet

IDML Export needs a small free companion app on your Mac. Figma plugins are not allowed to write files to your disk, so the plugin builds a description of your layout and the companion turns it into the .idml file.

  1. Download Monochrome-bridge.dmg from the link above.
  2. Open the DMG and drag the app to your Applications folder.
  3. Launch it once. A small icon appears in your menu bar — no window opens, and that is correct.
  4. Click that icon → Copy pairing token to clipboard, then paste the token into the "Monochrome Bridge is offline" panel in the plugin and press Save.

That last step is one-time. The token stays on your machine and is what stops any other program on your computer from talking to the companion.

2. It's installed, but it has stopped listening — this is normal

The bridge stops listening after 60 minutes with no activity, so it isn't holding a port open all day. The app itself keeps running: the menu-bar icon stays where it is, and its menu now reads Status: Stopped.

Click the menu-bar icon → Start bridge, then hit Retry in the plugin. That is the whole fix. The plugin cannot start the bridge for you — it is manual on purpose, so nothing of ours ever runs on your Mac without you opening it.

If you'd rather not do this after every long gap, the same menu has a Launch at login checkbox. It is off by default; switching it on makes the app open at login like any other application, so the icon is always there and one click restarts it. macOS will show you a "this app was added to your login items" notification the first time — that is macOS being transparent, not a warning.

To check the bridge by hand, open Terminal and run:

curl http://127.0.0.1:7331/ping

A JSON response means it's listening and everything is fine. No response means it is stopped — start it from the menu-bar icon.

3. macOS blocked it on first open

The app is signed and notarized by Apple, so this should not happen. If you do see "cannot be opened because the developer cannot be verified", the most likely cause is a partial or interrupted download.

  1. Delete the copy in /Applications and delete the DMG.
  2. Re-download from the link above and try again.
  3. If it still happens: right-click the app → Open → Open. This works, but please tell us — it means something is wrong with our signing, and we want to fix it rather than have people work around it.

4. Something else is using port 7331

The companion listens on 127.0.0.1:7331. If another program has claimed that port, it can't start. To check:

lsof -nP -iTCP:7331 -sTCP:LISTEN

If that lists something that isn't the Monochrome bridge, quit it and try again. If it lists an old copy of the bridge that isn't responding, quit it from the menu-bar icon (or, in Terminal, pkill -f services.py), then open Monochrome bridge again.

"Export failed" or the export hangs

  • Check the output folder is set — Setup tab. Without one, the companion has nowhere to write.
  • Check the folder still exists and is writable. External drives that have gone to sleep, and cloud-synced folders that are still catching up, are the usual culprits.
  • Very large frames take time. Image-heavy exports transfer real image data to the companion. Give it a moment before assuming it's stuck.
  • Try one frame. If a single frame exports and a batch doesn't, tell us which frame breaks it — that's the most useful bug report we can get.

The export ran, but the file is wrong

Read the compatibility report first. Before every export, IDML Export scans your frames and lists exactly what will convert cleanly, what will be approximated, and what cannot be converted at all. If something didn't survive the trip, the report almost certainly warned you about it. Nothing is ever silently substituted.

Common ones:

  • Fonts are missing in InDesign. The .idml references fonts by name; InDesign needs those fonts installed on the machine that opens it. The report flags unmapped fonts before you export.
  • Images are linked, not embedded. That's deliberate — it's what a production file should do. Keep the Links folder next to the .idml. If you point the plugin at your job's existing links folder, it will link your hi-res originals instead of re-exporting from Figma.
  • A gradient or blend mode looks different. InDesign has no equivalent for some of Figma's (angular and diamond gradients, for instance). These are approximated, and the report says so.
  • Components aren't permanent links until you save. Open the .idml and do Save As → .indd to make the document permanent.

"My export opens, but it's unusable"

If your file opens in InDesign, everything is in exactly the right place, and yet the file is plainly not production-ready — swatches stripped, type not workable — you are on the free tier. That is what the free export is: a proof that the conversion is correct, not a file you can ship.

The $6.99/month subscription unlocks the real, clean export. Everything else — scanning, the compatibility report, colour mapping, all of Setup — is free and stays free.

Windows

Not supported. Version 1 is macOS only, because the companion has to be signed for the platform it runs on. If there's demand, Windows is the next thing we'd build.

Privacy

Nothing about your design leaves your machine. The companion talks only to your own computer (127.0.0.1) and makes no outbound network connections at all. Full details: privacy policy.
